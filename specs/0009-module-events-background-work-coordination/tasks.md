## Notes for every task

- **Restore on this PC**: use the existing user-level proxy feed. Never commit a `nuget.config`. Export `DOTNET_ROOT` and `PATH` for the pinned SDK in `~/.dotnet` first.
- **No new packages**: new projects take only packages already pinned in `Directory.Packages.props` (`xunit.v3`, `Testcontainers.PostgreSql`, `Microsoft.NET.Test.Sdk`, and what the referenced projects bring). Update each touched project's `packages.lock.json` with `dotnet restore`, never by hand.
- **Fixture reuse**: `WT` reuses ISK-0004's fixture by linking its files (`<Compile Include="..\Iskender.Infrastructure.PostgreSql.Tests\Fixture\...">` and the embedded `init-roles.sql`), as `CT` and `tests/Iskender.Hosting.Tests` already do (`PCON` Test fixture rule 2). Fixture-only migrations are embedded in the test assembly only (`PCON` Test fixture rule 4).
- **Container-runtime tests**: tests that need Docker call the existing `RequirePostgreSql` or `RequireDocker` gate first, so they are skipped with their reason locally and fail when `CI=true` (`WCON` Test fixture rule 4).
- **Database clock**: every due-time, expiry, and retention decision uses `clock_timestamp()` in SQL, never the process clock (`WCON` Dispatch and apply rule 10).
- **Tests assert on codes**: assert on states, attempt counts, error codes, failure classes, event IDs, metric names and labels, exit codes, and readiness reasons, never on message text.
- **No fixed sleeps**: waits poll a state with a bound. A real flake is a blocker for `implement`, never a retry loop, a longer timeout added to hide it, or a skip.
- **Value-free telemetry**: no log field, span tag, metric label, error, or readiness answer holds a scope ID, item ID, idempotency key, payload byte, or configuration value (FR-034). Tests that check this use the canary of T055.
- **Architecture suite runs**: run it detailed to a file. If it stalls far beyond its usual time, kill and rerun it rather than waiting.
- **A failure you cannot fix**: report it. Never lower the 20 kill cycles of SC-001, skip a test in CI, add a suppression, or weaken an assertion to get past it.

## Phase 3: User Story 1 - Work survives a crash and is applied once (Priority: P1) 🎯 MVP
