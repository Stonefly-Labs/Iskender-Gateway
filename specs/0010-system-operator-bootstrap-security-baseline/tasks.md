# Tasks: ISK-0010 — System-Operator Bootstrap & Security Baseline

**Input**: Design documents from `specs/0010-system-operator-bootstrap-security-baseline/`

**Prerequisites**: plan.md, spec.md, research.md (R1 to R21), data-model.md, quickstart.md, contracts/operator-security.md (version 1), and the revisions contracts/container.md (version 3), contracts/hosting.md (version 4), contracts/persistence.md (version 4), contracts/local-environment.md (version 3)

**Tests**: Required. The approved acceptance ("uninitialized admin routes deny access; bootstrap token cannot be reused"), FR-043, and SC-001 to SC-010 name test outcomes, so each task delivers its code and its tests together. Write the tests first and watch them fail, but commit only when the suite is green, because every commit must leave the build and tests passing (plan, "Implementation approach").

**Scope guard**: No local account, password, session, cookie, OIDC login, organization or project role, project-level grant, API key, management resource API, or management UI (spec Out of Scope). No production implementation of `IOperatorPrincipalResolver` and no consumer of `IEnrollmentCodes`. No new production project, package, image, executable, or Dockerfile, so the module dependency rules contract stays at version 5 (R1). No public member of `Iskender.Hosting` changes, and its harness baseline stays (FR-040). `core-contracts` goes from 6 to 7 with additions only; `providers-abstractions` and `policy-sdk` gain nothing. The redemption uses no advisory lock or coordinator (AV-2); the only advisory lock is the issuers' transaction-scoped mutual exclusion of R6. No function bypasses row-level security, and the operator scope touches no tenant table. Every readiness answer, stop sequence, and the three smoke readiness answers stay byte for byte (FR-021, FR-036). No tracked file holds a token, enrollment code, private key, or certificate. CI stays at 10 checks (AV-7). No change under `.specify/` or to `.iskender/grounding.yaml`, and no edit to an earlier spec's published contract file except the in-place table rows that `public-contracts-and-versioning` itself allows (R17): the new versions are already in this spec's `contracts/` directory.

## Phase order

Phase 2 builds what every story stands on: the error codes and resource type, the Identity and Telemetry port types, the token text, the `audit` and `identity` migration modules and their stores, the adapter registration, the operator section, the telemetry definitions, and the identity test project with its fixture. US1 (Phase 3) adds the admin surface, its pipeline and gate, the route-declaration check, and the installation route, and is the MVP: the first half of the approved acceptance. US2 (Phase 4) adds redemption, the redemption routes, the limit, and the `bootstrap` command's library, and proves the second half, with the 20 × 50 concurrency runs. US3 (Phase 5) proves privilege checks. US4 (Phase 6) adds the transport modes, TLS, the control-plane container wiring, and the enforced anonymous endpoint inventory. US5 (Phase 7) proves the audit trail, US6 (Phase 8) recovery and enrollment, and US7 (Phase 9) embedding and the developer topology. Phase 10 runs the telemetry canary, publishes the documentation, runs the quickstart, and runs the whole gate.

## Notes for every task

- **Restore on this PC**: use the existing user-level proxy feed. Never commit a `nuget.config`. Export `DOTNET_ROOT` and `PATH` for the pinned SDK in `~/.dotnet` first.
- **No new packages**: `Iskender.Management` gains `<FrameworkReference Include="Microsoft.AspNetCore.App" />`, not a package. New test projects take only packages already pinned in `Directory.Packages.props`. Update each touched project's `packages.lock.json` with `dotnet restore`, never by hand.
- **Fixture reuse**: `IT` reuses ISK-0004's fixture by linking its files from `PGT/Fixture/` (`PostgreSqlFixture`, `ClassDatabase`, `RequirePostgreSql`, `TestCredentialProvider`, `TestSettings`, `Owners`, `CapturingDiagnostics`, and the embedded `init-roles.sql`), as `tests/Iskender.Work.Tests` already does (`PCON` Test fixture rules 2 and 5).
- **Container-runtime tests**: tests that need Docker call the existing `RequirePostgreSql` or `RequireDocker` gate first, so they are skipped with their reason locally and fail when `CI=true` (`OCON` Test fixture rule 4).
- **Database clock**: token expiry, `issued_at`, `consumed_at`, `initialized_at`, and `recorded_at` use `statement_timestamp()` in SQL, never the process clock (FR-005, R5).
- **Secrets in tests**: every token, enrollment code, certificate, and key is generated at run time. A test never holds a literal token, and never writes a key outside a temporary directory it deletes.
- **Tests assert on codes**: assert on HTTP statuses, error codes, reason classes, audit actions and results, event IDs, metric names and labels, exit codes, and readiness bodies, never on message text.
- **No fixed sleeps**: waits poll a state with a bound. A real flake is a blocker for `implement`, never a retry loop, a longer timeout added to hide it, or a skip.
- **Value-free telemetry**: no log field, span tag, metric label, error, audit record, or readiness answer holds a token, a hash, a principal ID, a network address, or a configuration value (FR-038). Tests that check this use the canary of T052.
- **Architecture suite runs**: run it detailed to a file. If it stalls far beyond its usual time, kill and rerun it rather than waiting.
- **A failure you cannot fix**: report it. Never lower the 20 × 50 runs of SC-002, skip a test in CI, add a suppression, or weaken an assertion to get past it.
