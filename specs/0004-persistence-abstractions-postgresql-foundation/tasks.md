## Path Conventions

`CC` means `src/Iskender.Core.Contracts`, `PORTS` means `src/Iskender.Domain/Ports` (namespace `Iskender.Domain.Ports`), `PG` means `src/Iskender.Infrastructure.PostgreSql`, `PGT` means `tests/Iskender.Infrastructure.PostgreSql.Tests`, `DT` means `tests/Iskender.Domain.Tests`, `CCTests` means `tests/Iskender.Core.Contracts.Tests`, and `Compat` means `tests/Iskender.Contracts.Compatibility.Tests`. Rules, codes, safe messages, keys, reasons, and event IDs come from `contracts/persistence.md` (version 1), type shapes from `data-model.md`, and design decisions from `research.md` (R1 to R24). Framework code in `PG` uses only the namespaces `Iskender.Infrastructure.PostgreSql`, `.Migrations`, `.Health`, and `.Diagnostics`. Test namespaces in `PGT` mirror their folders (for example `Iskender.Infrastructure.PostgreSql.Tests.Concurrency`), so the `--filter-class` patterns in the quickstart and T037 select whole folders.

## Phase order

The user stories are ordered by dependency, not only by priority. US1 (migrations) comes first and is the MVP, because the fixture modules' tables, row-level security policies, and migrated template database that US2 and US3 test against are created by the migration runner. US3 (isolation) adds the table descriptors and fixture repositories that US2's concurrency tests use, so it comes before US2. US4 (health) needs US1's history and lock. US5 proves the fixture's own guarantees and can run any time after Phase 2.

## Notes for every task

- **Restore on this PC**: Use the existing user-level proxy feed. Never commit a `nuget.config` or put that feed in CI. Export `DOTNET_ROOT` and `PATH` for the pinned SDK in `~/.dotnet` first.
- **Lock files**: After adding a project or changing a package reference, run `dotnet restore Iskender.slnx --force-evaluate` and commit each changed `packages.lock.json`, since CI restores in `--locked-mode` (ISK-0001 rule B2). Package versions go only in `Directory.Packages.props` (rule B1).
- **Version tags**: every new `ErrorCodes` field carries `[ContractVersion("core-contracts", 3)]` from the commit that adds it. Regenerate `Compat/baselines/core-contracts.surface.txt` and `Compat/baselines/registries.json` in the same commit as any surface or registry change.
- **Owning spec**: every new type in `PORTS` and `PG` has an XML comment naming ISK-0004 as its owning spec (FR-003).
- **Failures are `GatewayException`s**: ports throw only `new GatewayException(code)`. A faulted unit records its `PersistenceFailure` on `IUnitOfWork.Failure` before throwing (research R9). Never attach an inner exception, SQL, or server text.
- **Nothing sensitive in text**: no log field, metric label, activity tag, exception message, or probe result holds a host, port, database name, user name, password, connection text, SQL, parameter value, owner ID, or server error text (FR-026, FR-032). Parameters are positional (`$1`), never concatenated (research R2).
- **Tests assert on codes**: assert on the `ErrorCode`, failure class, reason, row counts, and catalog state, never on message text.
- **Container tests**: every test that needs PostgreSQL calls `RequirePostgreSql()` first, so it is skipped with a reason locally without a container runtime, and fails when `CI=true` (FR-035).
- **Concurrency tests**: start contenders with a barrier and assert on final state, never on timing (plan, Risks).
- **A failure you cannot fix**: report it. Never lower a count in SC-002 or SC-003, skip a container test in CI, add a suppression, or weaken a rule to get past it.
