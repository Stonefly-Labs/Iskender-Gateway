## Notes for every task

- **Restore on this PC**: Use the existing user-level proxy feed. Never commit a `nuget.config`, and never put that feed in a file under `local/`, a Dockerfile, or CI. Export `DOTNET_ROOT` and `PATH` for the pinned SDK in `~/.dotnet` first.
- **`bash` 3.2**: every script and `10-provision.sh` runs under macOS's `/bin/bash` 3.2. No associative arrays, `mapfile`, `readarray`, `${var,,}`, `${var^^}`, `[[ -v ]]`, `|&`, `wait -n`, `declare -n`, or expansion of an empty array under `set -u` (R12). Use only `git`, `docker`, `tr`, `head`, `sed`, `grep`, `cat`, `mkdir`, `chmod`, `rm`, `sleep`, and `date`. Each script starts with `#!/usr/bin/env bash` and `set -euo pipefail`.
- **Executable bit and endings**: add each script with `git add --chmod=+x`, so Git records mode `100755`. Every file under `local/` is LF. `.gitattributes` already has `* text=auto eol=lf`.
- **Value-free output**: scripts write messages to standard error, naming a check, service, variable, or prerequisite, never a password, database name, login name, secret reference name, or document value (FR-017, LCON Scripts). No `set -x` in any script.
- **Exit codes**: 0, 1, 2, and 64 exactly as `LCON` Exit codes lists them. `migrate.sh` passes through the job's own code.
- **Tests assert on codes**: assert on exit codes, event IDs, readiness reasons, error codes, service states, and observed files and resources, never on message text, except where a test checks that a message names a variable, service, or check by its fixed name.
- **Container-runtime tests**: tests that need Docker, `bash`, or `git` call `RequireLocalTools` (T009) first, so they are skipped with a reason locally without them, and fail when `CI=true` (`LCON` Test fixtures rule 3).
- **Isolation**: every container test runs in its own `LocalTopology` (T011), with its own project name `iskender-local-t<12 hex>` and free ports, so it never touches a developer's `iskender-local` project or ISK-0007's `isk-` projects, and disposes it even on failure.
- **No fixed sleeps**: waits poll a state with a timeout. A real flake is a blocker for `implement`, never a retry loop or a skip.
- **A failure you cannot fix**: report it. Never lower the 5 cycles of SC-001, skip a test in CI, add a suppression, add a licence to `check-license.sh`, or weaken an assertion to get past it.

## Implementation Strategy

### MVP first

1. Phases 1 and 2: the wiring, documents, library, and fixtures.
2. Phase 3: the documents proven without a container runtime.
3. Phase 4: a fresh copy starts the hardened topology. **Stop and validate**: the first half of the acceptance criterion holds.

### Incremental delivery

4. Phase 5, then Phase 6: the migration job and the smoke assertions. The acceptance criterion's start-and-smoke pair now holds.
5. Phase 7: reset proven against a control project and the missing-password-file state.
6. Phase 8: the `dependencies` mode and native runs.
7. Phase 9: the 5-cycle acceptance test, the documentation, the quickstart, and the gate.

Each task is committed and pushed on its own, with the build and every test green at each commit.
